# 《交互设计的原则和目标》内容总结

对应课件：[[3 交互设计原则与目标.pdf]]（48 页）

## 核心内容

1. **交互框架与 EEC 模型**
   - 交互框架帮助设计者结构化设计过程、识别问题并界定问题领域。
   - 执行/评估活动周期（Execution-Evaluation Cycle，EEC）从用户视角描述一个动作的完成过程：用户形成目标和意图，执行操作，观察系统状态，再评估结果。
   - “目标”不等于“意图”：一个目标可能有多种实现意图。执行隔阂是用户想做的动作与系统允许动作之间的差异；评估隔阂是系统实际状态与用户预期之间的差异。
   - 扩展 EEC 模型进一步区分用户的任务语言、输入语言、系统内核语言和输出语言，强调设计者要降低不同语言之间的翻译成本。

2. **可用性目标**
   - **易学性**：新用户学习完成任务的难易程度，关注学习曲线的起始阶段。
   - **易记性**：用户再次使用时能否迅速回忆操作方式；有意义的名称和图标、稳定的位置、合理分组、通用惯例和多通道冗余都有帮助。
   - **效用性**：系统是否提供用户需要的正确功能。
   - **高效率**：熟练用户学会系统后能否持续保持较高生产率。
   - **安全性/低错误**：避免危险状态、误操作和不可恢复的后果，并提供恢复路径。
   - 可用性指标通常是客观的，但不能替代用户对产品的主观感受。

3. **用户体验目标与可用性的关系**
   - 交互系统还可能追求愉快、有趣、吸引人、令人信任、令人兴奋或具有说服力等体验目标。
   - 可用性与体验目标并不总是一致：更具挑战性的游戏可能降低易用性，却提升趣味；电商设计也可能以说服购买为目标，而不是让任务执行效率最高。
   - 因此设计者需要明确具体场景中的优先级，理解安全、效率、趣味、满意度等目标之间的权衡，并警惕会损害用户利益的 Dark Pattern。

4. **简易可用性工程**
   - 以人为中心的可用性工程过程包括了解用户、竞争性分析、设定目标、用户参与设计、迭代设计和发布后的持续工作。
   - 课件重点介绍四种简化方法：用户与任务观察、场景/原型、简化的边做边说（Thinking Aloud）和启发式评估。
   - 水平原型减少功能深度以观察界面表层；垂直原型减少功能数量但完整实现选定功能。
   - 边做边说可以揭示用户为什么采取某种行动及其误解；启发式评估应由多个不同人员参与，以降低个人偏见。课件给出的经验公式表明，约 5 名专家可发现约 80% 的可用性问题。

5. **设计规则与启发式原则**
   - Alan Dix 的基本规则可概括为可学习性、灵活性和健壮性。
   - Shneiderman 的黄金规则包括：保持一致、考虑普遍可用性、提供信息丰富的反馈、提供明确的结束信息、预防并处理错误、让操作容易撤销、支持用户的内部控制点、减轻短时记忆负担。
   - Nielsen 的十项启发式原则包括：系统状态可见、系统与现实世界吻合、用户有控制权和自主权、一致性与标准化、避免出错、依赖识别而非记忆、灵活高效、帮助识别诊断和恢复错误、提供帮助与文档、审美与最小化设计。

## 关键启示

- 交互设计既要帮助用户完成任务，也要让用户理解系统当前状态，并能预测、控制和恢复操作结果。
- 设计原则不是脱离场景的硬规则。它们来自经验，可能相互冲突，必须结合用户、任务、环境和产品目标进行取舍。
- “可用”是可度量的设计目标，“体验”是更广泛的感受目标；高质量产品需要同时处理二者，而不是用其中一个替代另一个。
