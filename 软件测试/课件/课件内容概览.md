# 软件测试课件内容概览

课程：[软件测试（2026）](https://selearning.nju.edu.cn/course/view.php?id=418)

本目录保存课程“课件”栏目中的全部 5 个 PDF 文件，并按照课程页面显示顺序整理。下面是对每个课件的内容总结。

## 1. [[1.1.1常用测试术语.pdf]]

- 页数：19 页
- 主要内容：介绍软件测试的基本概念和常用术语，包括测试、测试用例、测试数据、测试预言、测试环境、测试报告、缺陷报告、待测软件（SUT）、待测程序和待测系统等。
- 核心概念：测试用例可表示为 `<t, o, θ>`，分别表示测试输入、测试预期输出和测试环境；测试集由多个测试用例组成。测试的目标是通过实验发现缺陷、验证功能或评估非功能属性，但测试只能证明发现了问题，不能证明软件绝对没有问题。
- 重点讨论：测试数据应尽量接近真实数据分布，并覆盖异常和边界场景；测试预言负责判断实际结果是否正确；测试环境不仅包括操作系统、数据库、网络和硬件，也包括模型版本、系统提示词、温度、上下文、RAG 数据、工具状态和外部 API 等 LLM 运行条件。
- 测试报告：至少应记录测试环境 `θ`、测试输入 `t`、测试输出 `o` 和结果描述 `d`，使问题能够被理解、复现和定位。
- 课件还以三角形程序为例说明如何从测试需求、测试用例和测试结果形成测试报告，并引出 AI 生成代码和 AI 测试助手场景下的测试责任问题。

## 2. [[1.1.2常用测试分类.pdf]]

- 页数：21 页
- 分类框架：测试分类主要回答三个问题：能看到多少内部信息、处于软件生命周期的哪个层级、想验证哪一种质量属性。
- 按内部信息分类：白盒测试依赖源代码并关注内部结构和路径覆盖；黑盒测试从用户、界面和外部功能出发，依据规格说明设计用例；灰盒测试介于两者之间，通过有限的内部知识或运行现象辅助测试。灰盒测试不等于白盒测试与黑盒测试的简单相加。
- 按开发流程分类：单元测试验证最小可测试单元，集成测试验证模块之间的协作，系统测试验证完整系统及其真实使用环境，验收测试验证用户需求和业务流程是否达到验收标准。该部分结合 V-Model 说明不同层级测试之间的关系。
- 按质量属性分类：功能测试验证需求功能，性能测试关注响应时间、吞吐量、并发和资源利用率，安全测试关注漏洞、身份验证和授权，兼容性测试关注不同设备与软件环境，易用性测试关注界面、交互和用户体验。
- AI 测试启示：如果同一个 LLM 先生成程序、再根据自己的实现生成测试，可能会把错误需求理解重复一遍，测试也可能只验证“代码已经做了什么”，而不是“需求应该做什么”。因此测试设计需要保持独立的规格依据，并综合使用多种分类方法。

## 3. [[1.2.1三角形程序Triangle.pdf]]

- 页数：14 页
- 问题背景：输入三个 1～100 的整数 `a、b、c`，根据三边关系输出等边、等腰、普通或无效三角形；课件以“只能测试少量次数时如何选择数据”引入测试设计。
- 需求与实现：明确输入范围、三角形合法性、三边相等和两边相等等需求，并分别展示 Python、C、Java 和仓颉语言实现，比较相同需求在不同语言、类型系统、编译器、运行平台和依赖环境下的测试差异。
- 测试重点：应覆盖等价类、边界值、无效输入、退化三角形、不同边相等组合以及条件分支。Python 的动态类型需要额外关注类型组合和依赖版本；C 需要关注指针、内存、编译器和平台差异；Java 和仓颉则可利用静态类型检查和对应测试框架。
- 深层讨论：相同需求并不意味着不同代码的测试完全相同，代码结构和实现语言会影响测试策略。若未来同一需求由 LLM 生成多种实现，仅靠开发者手写少量测试可能不足，还需要独立测试生成、分类器/神经网络实现的样本研究，以及针对机器学习程序的测试方法。

## 4. [[1.2.2日期程序NextDay.pdf]]

- 页数：12 页
- 问题背景：输入年、月、日，返回下一天。程序看似简单，但闰年、月末、年末和非法日期会产生大量测试风险。
- 需求与实现：要求年份在 1～9999、月份在 1～12、日期在 1～31，并正确计算下一天。课件重点介绍闰年规则：普通年份每四年一闰，但整百年份只有 400 的倍数才是闰年，因此 2000 年是闰年而 1900 年不是。
- 测试重点：覆盖普通日期、各类月末、2 月 28 日、闰年 2 月 29 日、非闰年 2 月 28 日、世纪年、400 倍数世纪年、年末和非法日期；同时检查年份上下界和日期边界是否充分。
- 方法总结：NextDay 体现了“分支与计算结合”的测试难点，适合综合使用等价类、边界值、控制流和数据流分析。课件还指出测试用例可能遗漏普通闰年、下界越界和 8 月 31 日等高价值场景，并以农历与公历转换作为课后延伸练习。

## 5. [[1.2.3均值方差程序MeanVar.pdf]]

- 页数：13 页
- 问题背景：输入长度为 `L` 的实数数组，返回平均值和方差。课件通过“数学公式完全等价的两个程序，软件行为是否一定等价”引出数值程序测试。
- 需求与实现：介绍总体方差与修正方差的公式，并展示 C 和 Java 实现。测试需要明确数组元素为实数、数组长度至少为 1，以及使用总体方差还是样本修正方差等隐含需求。
- 算法比较：比较先求平均数再计算离差平方的基本公式、通过二阶矩计算方差的公式，以及适合流式数据的增量式算法。增量式算法可以避免每次新增数据都重新遍历全部数据。
- 测试重点：数学等价不保证程序行为等价，需要关注循环边界、空数组、单元素数组、整数或浮点溢出、极端输入、NaN/Inf、算法复杂度、运行速度和数值稳定性。特别是当数据值很大但彼此差异很小时，应比较不同实现的精度和稳定性。
- 核心结论：测试不仅要确认结果“数学上正确”，还要验证程序在具体数据类型、规模、运行环境和精度要求下是否可靠。

## 课件之间的关系

前两份课件建立软件测试术语和分类框架；后三份课件通过三角形分类、日期计算和均值方差三个程序，分别展示分支逻辑、边界条件、语言实现差异、数值计算和算法稳定性对测试设计的影响。整体主线是从“理解测试对象和测试依据”逐步过渡到“针对不同程序特征设计有证据的测试策略”。
